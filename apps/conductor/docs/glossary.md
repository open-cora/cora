# Glossary

*The words this project shares with the keeper, and what each one is pinned to.*

Every term here is the keeper's, copied rather than linked, because the two
projects ship separately and a shared word that drifted would be worse than a
word written twice. The keeper's own glossary is the longer one: it also holds
the vocabulary of bounded contexts, events and projections, none of which this
project has.

A term used here and not listed is either plain English or this project's own,
and this project's own are defined where they are declared.

## The work

- **Operation.** A runnable routine this system holds a record of: the name the engine knows it by, and the JSON Schema a run of it must satisfy. Defined, not registered: nothing anywhere pairs that name with that schema until the record says so.
- **Routine.** The thing out in the engine that an operation's name points at. Not modelled here, and named with a plain word rather than a term, because this system holds a reference to it and never the thing itself.
- **Procedure.** A routine this system composed, written down: an ordered list of steps, each naming what it touches. The contrast with an **operation** is who authored the routine. An operation names something an engine already has and a procedure names something nothing knows until this system says so, which is why an operation's name is a handle in someone else's vocabulary and a procedure's steps are not.
- **Step.** One element of a procedure: a routine, the parameters it is given, and what it holds while it runs. One kind, because what a step does is hand a routine over and sending a record to a value is one of those routines. Every step declares what it touches; a **set** is the one whose declaration is derived, because the record it names is the thing it holds.
- **Scope.** One piece of a device namespace, named as a string and claimed whole. Stored here as written and parsed nowhere: the grammar belongs to whatever drives the procedure, and the arithmetic over collisions runs in that process.
- **Execution.** One traversal of a procedure: the record this system opens when it dispatches one, and how far the thing driving it got. Every step of it is either reported by a driver or left unreported, and the record says which.
- **Execution status.** How far an execution has got: Dispatched, Claimed, Running, Parked, Ready or Ended. Derived in the fold from which events the stream carries, never stored. Dispatched is the one transient state in this tree: the record exists and nothing has taken it up, which is a state that only becomes possible once this system hands work out.
- **Parked.** Of an execution: its walk stopped at a step whose work is still running elsewhere, and said so rather than ending. The steps after that one carry no outcome, because nothing has reached them. Waiting rather than abandoned, which is the difference from a walk whose conductor died: that one reads as Running with steps unreported and says nothing.
- **Ready.** Of a parked execution: whatever watches the work its parked step handed off has reported that work ended, so a conductor may claim it and walk on from the step after. Ready after a failure as well, because it means the walk may be taken back and not that the work went well; the conductor that takes back a failure reports the rest skipped and closes it.
- **Engine state.** What an engine was reported to have done to the run one step opened: Running, Paused, Completed, Aborted or Failed. The second of two observers of one step, beside the driver's outcome, and the two are allowed to disagree because neither is reliable and collapsing them would make this system pick a winner between two claims it cannot check.
- **Run.** The carrying-out a step causes: an engine handed a routine, and whatever it did about it. The act rather than the element, which is **step**. It used to name both, and the two parted when a set stopped being a second kind of step and became a routine like any other, leaving one word needed for the element and one for the act. Chosen over **acquisition**, which names collecting data, when what a step actually does is delegate. A run may collect nothing, and the ones that transfer or compute will collect nothing at all. What an engine did with it is on the step, as an `engine_reference` and an engine state.
- **Setup.** The values a beamline's conductor applies when it runs one operation, under the name a run's `config` parameter carries, with the schema those values satisfy. One per beamline, per operation, per name, and held in the record rather than in a file on a host, so the record says what a run was asked for down to the value. The work intake reads the revision a step was pinned to and hands the engine its settings with the step's override written over them. Not the device configuration the record declines to hold, which is what a station's hardware is set to: a setup is values an engine is asked to apply, the same kind of thing a run's parameters are. At a beamline the word also names the physical arrangement of hardware around a sample, and that sense is not modelled here.
- **Revision.** Of a setup: one numbered state of its settings and their schema, 1 at definition and one more each time it is revised. A setup is revised and never edited, so every revision stays readable.
- **Pinned.** Of a step of an execution: fixed, at dispatch, to the setup its run names and the revision of it that was latest then, so a revision made afterwards changes nothing that step was asked to run with. A step that takes no setup is pinned to nothing.
- **External reference.** An open-scheme `(scheme, value)` pair naming something in a system outside this one. The scheme names the issuing authority and the value is opaque to it. A dataset carries one, because data this system cannot point back at cannot be found.
- **Reported.** Of a step or of an engine's account of one: performed somewhere else, and made known to this system by someone or something telling it afterwards. The contrast pair is **composed**, of the work this system authored itself. It claims only what this system can back: that it was told. "Witnessed" would fail that, because to witness is to have been present and able to vouch, and this system was neither.
- **Engine.** Whatever actually runs a routine, outside this system. Named by role rather than by product, because which one a deployment runs is a deployment's fact.
- **Control system.** Whatever actually drives and publishes a device, outside this system. Named by role rather than by product, for the same reason **engine** is: which one a deployment runs is a deployment's fact.
